# NextRole discovery strategy and next milestones

Review date: 17 October 2026 UTC. This is a plan, not a claim of implemented integrations. RELEASE-14.md and PM-EXECUTION-STATUS.md distinguish delivered code from proposed work.

## Architecture decision

Retain Vinext/React, the authenticated Cloudflare Worker, D1, owner-authorized resumable maintenance and existing job/tracking identifiers. A rewrite would add migration risk without resolving missing source rights or relevance quality. The v14 registry removes the need to edit source code for each ATS employer. The next expansion should first remove the full-catalogue-per-user response bottleneck, then add a measured second discovery category.

Keep discovery separate from evidence retrieval. A search result creates a candidate URL, not a published job. Admit it only after permitted retrieval of employer/authorized source evidence, schema validation, safe official application-link validation, provenance and duplicate resolution. Use deterministic structured extraction first; optional schema-constrained LLM extraction must retain exact source spans, unknown fields and a content hash. Never turn snippets or model output alone into verified jobs.

Future persisted records should separate listing identity, source observations and normalized facts. Record source/adapter version, URL, content hash, discovered/retrieved/verified times, completeness, extraction evidence, closure state and cost. Retain source-run counters/history for the quality denominator. The v14 `source_runs` table is latest status, not that history. Make the schema addition additive and keep all current application keys.

The search budget must count search, retrieval, extraction, verification and storage. Track **cost per new, current, relevant, deduplicated job**, not cost per returned row. Use a hard daily/monthly cap, cache identical cohort queries and stop when the cap is reached. LLM calls should be optional and restricted to content that structured parsers cannot interpret. Provider list prices above must be rechecked before purchase.

## Prioritized delivery plan

| Order | Milestone | Impact / effort / risk | Acceptance criteria |
| --- | --- | --- | --- |
| 1 | Catalogue pagination and durable discovery measurements | High / medium / medium | Server-side indexed selection with stable cursors; preserve For you/Needs review/All openings and Interested/Applied semantics; identical card/detail/alert decisions; no cross-user data; instrument source runs/usable-job denominators; 10,000-listing fixture with a bounded first-page payload; measured query/load results with limitations. |
| 2 | Browser pilot and release validation | High / small–medium / low locally | Verify eye, keyboard focus, mobile layout, profile confirmation/conflict, import, history/copy/review/download, export/deletion, source registration and recovery in supported browser control; resolve blocking issues; compare actual hosted state. Publication and production migration still require approval. |
| 3 | Permissioned search-discovery pilot | Very high / medium–large / medium–high | Approved account/rights/budget; disabled-by-default configuration; persisted candidate/retrieval/extraction states; evidence-required admission; safe fixed/approved-domain retrieval; retries/closure/dedup; at least one genuinely new source category; no paid calls after budget exhaustion. |
| 4 | Labelled relevance and coverage evaluation | High / medium / low | At least 100 human-reviewed target-role records across providers and locations; report top-10 precision, mandatory-rule violations, unknowns, false rejections, duplicate/broken/stale rates and source diversity with actual denominators. Set launch thresholds before interpreting results. No fabricated market coverage. |
| 5 | Application-preparation refinement | High / medium / low–medium | Improve answer quality from confirmed facts and human feedback; more permitted form adapters; verified user edits/revision history; practical one-/two-page resume workflow. A compiled-LaTeX service needs a separately reviewed isolated toolchain, privacy/retention plan and cost. |
| 6 | Assessment/interview deadlines and next actions | Medium–high / medium / low–medium | Editable confirmed dates/timezones, reminder recovery, clear official/reported/generated provenance; suggestions based on explicit state with small-sample caveats. Email delivery only after opt-in and provider setup. |
| 7 | Optional assisted submission | Potentially high / large / high | Settings OFF by default; rules with mandatory pass/fail/unknown eligibility; unknown critical fields route to review; duplicate/open checks; permitted adapters only; approval, pause and audit; attestations/CAPTCHA handled by the user; success requires actual employer confirmation. |

The next smallest high-value engineering milestone is order 1. Increasing boards or search volume before removing full-catalogue responses would increase per-user memory, network traffic and repeated work. This is a discovery scalability prerequisite, not a change in product priority. Auto-Apply follows a useful, measured manual workflow; speculative application volume is not a success metric.
